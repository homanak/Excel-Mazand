# نمایشگر زندهٔ ارتباط فایل‌ها

یک سرور کوچک که همان ۹ فایل تحویلی را **در مرورگر** باز می‌کند تا بدون اکسل ببینید
لینک‌ها و ارجاع‌های بین فایل‌ها واقعاً کار می‌کنند.

```bash
.venv/bin/python build4/serve_all.py --port 8080    # همه‌چیز در یک سرور
```

سپس `http://<host>:8080/` را باز کنید. **یک سرور، همهٔ مسیرها:**

| مسیر | چه چیزی |
|---|---|
| `/` | نمایشگر زندهٔ ۹ فایل |
| `/download` | صفحهٔ دانلود (زیپ + فایل‌ها) |
| `/f/<name>` | هر فایل xlsx یا README |
| `/Mazandasht_v04.zip` | بستهٔ کامل |
| `/health` | پاسخ کوتاه برای بررسی سلامت |

اگر ایندکس نبود، سرور خودش با `explore_index.py` می‌سازد و اگر `openpyxl` نبود، از نسخهٔ
ذخیره‌شدهٔ `build4/explore_index.json.gz` استفاده می‌کند (در گیت هست).

> **پس از ریست ورک‌اسپیس** فقط همین یک دستور لازم است: `python3 build4/serve_all.py --port 8080`.
> ایندکس در `build4/explore_index.json.gz` کامیت شده، صفحهٔ دانلود و زیپ هم اگر نبودند خود سرور
> می‌سازد؛ نه venv لازم است نه `openpyxl` (آن‌ها فقط برای بازسازی ایندکس/فایل‌ها لازم‌اند).

> **چرا قبلاً باز نمی‌شد؟** سرور قبلی به درخواست `HEAD` جواب `501 Unsupported method` می‌داد و
> پروکسی پیش‌نمایش پیش از باز کردن صفحه همان `HEAD` را می‌فرستد. `serve_all.py` هم `GET` و هم
> `HEAD` (و `Range` برای دانلود) را جواب می‌دهد.

## چه چیزی نشان می‌دهد

| بخش | کار |
|---|---|
| **کاربرگ** | هر شیت مثل اکسل کشیده می‌شود: رنگ، ادغام، عرض ستون، ارتفاع ردیف، چاپ. سلول‌های آبی لینک دارند و با یک کلیک همان‌جایی می‌روند که اکسل می‌رفت. |
| **بازرس سلول** | با کلیک روی هر سلول: مقدار، فرمول کامل، مقصد لینک، و فهرست «می‌خواند از» / «چه کسانی می‌خوانند». چیپ‌های `Sync · I10` مستقیم به همان سلول منبع می‌روند. |
| **نقشهٔ ارتباطات** | دو سطح: **فایل** (۹ گره و خطوط ارجاع/لینک بین‌شان) و **شیت** (۹۴ گره). خطوط با جریان متحرک نشان داده می‌شوند؛ کلیک روی هر خط، سلول‌های نمونه‌اش را با دکمهٔ پرش نشان می‌دهد. |
| **تور زنده** | ۱۰ ایست از مادر تا گزارش‌ها: `00_Master/Sync → Acc → 01_Entry/Sync → Scale → Book → Bill → Home → 02_Bank/Txn → 03_Report/LBRep → 04_Inv/Inv`. هر ایست شیت واقعی را باز می‌کند و سلول کلیدی را روشن می‌کند. |
| **جست‌وجو** | در متن‌ها و فرمول‌های هر ۹ فایل (مثلاً `C001` یا `OpTbl`) و پرش به همان سلول. |

## مدل ارتباطی که نمایش می‌دهد

1. **`00_Master`** تنها منبع دادهٔ ثابت است (حساب‌ها، عملیات، سبدها، بانک‌ها، پارامترها).
2. هر فایل یک شیت **`Sync`** قفل‌شده دارد که کپی همان داده است؛ نام‌هایی مثل `AcctTbl` و
   `OpTbl` به همین شیت اشاره می‌کنند، پس همهٔ فرمول‌ها یک منبع دارند.
3. شیت‌های هر فایل از `Sync` خودش می‌خوانند و کارت‌های `Home` و نوار «فایل‌های همراه» با
   مسیر نسبی فایل‌ها را به هم وصل می‌کنند.

## نکته‌های فنی

* ایندکس در `build4/_explore/index.json(.gz)` ساخته می‌شود (≈۵ MB خام، ۰٫۷ MB فشرده) و در
  گیت نمی‌آید؛ برای همین خود فایل‌های ۱۵ مگابایتی هر بار خوانده نمی‌شوند. اگر فایل‌های
  `Mazandasht_v04/` عوض شدند، ایندکس را دوباره بسازید.
* از هر شیت حداکثر ۲۴۰ ردیف (شیت‌های بزرگ‌تر: ۱۶۰ ردیف) و ۳۴ ستون اول ذخیره می‌شود؛ برای
  همان بازبینی لینک‌ها کافی است و بقیهٔ ردیف‌ها فقط شمارش می‌شوند.
* مقدار سلول‌های فرمولی **محاسبه نمی‌شود** (اکسل آن‌ها را حساب می‌کند)؛ نمایشگر فرمول را
  با نشانهٔ `ƒ` و متن کامل در بازرس نشان می‌دهد. برای اطمینان از اعداد، همان
  `build4/invcheck.py` و موتور `formulas` هست که در README اصلی گزارش شده.
* پاسخ‌های بزرگ با gzip می‌روند (مثلاً شیت `Scale`: ۴۳۰ KB → ۵۶ KB).
* همه‌چیز فقط-خواندنی است؛ هیچ فایلی تغییر نمی‌کند.

## API

| مسیر | خروجی |
|---|---|
| `/api/meta` | فهرست ۹ فایل، شیت‌ها، نام‌های تعریف‌شده |
| `/api/sheet?f=&s=` | پنجرهٔ سلول‌ها، استایل‌ها، فرمول‌ها، ادغام‌ها، لینک‌ها |
| `/api/flow?f=&s=` | این شیت چه می‌خواند و چه کسانی می‌خوانندش |
| `/api/graph` | ۲۴۰ یال: `formula` (ارجاع فرمول)، `file` (باز کردن فایل دیگر)، `sheet` (پرش شیت)، `sync` (کپی مادر) |
| `/api/find?q=` | جست‌وجو در متن و فرمول |
| `/api/health` | تاریخ ایندکس و شمارش‌ها |

## یک یافته که در نقشه دیده می‌شود

فایل‌های `03_Report` / `04_Inv` / `05_Bal` / `06_Buyers` شیت **Home** ندارند، پس خودشان هیچ
لینک خروجی به فایل‌های دیگر نمی‌دهند (ستون «لینک خروجی» با ⚠ نشان داده می‌شود)؛ فقط از کارت‌های
`00_Master` / `01_Entry` / `02_Bank` / `07_Demo` / `08_Dash` باز می‌شوند. اگر بخواهید، همان نوار
«فایل‌های همراه» را می‌شود روی اولین شیت این چهار فایل هم گذاشت (`build4/relink.py`).
